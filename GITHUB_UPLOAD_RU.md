# Публикация EtherTV в GitHub

## Загрузка через сайт GitHub

1. Создайте новый пустой репозиторий на GitHub. Не добавляйте при создании README, `.gitignore` или лицензию — они уже находятся в проекте либо намеренно не заданы.
2. Распакуйте этот архив на устройстве.
3. Откройте созданный репозиторий и выберите **Add file → Upload files**.
4. Загрузите содержимое папки `EtherTV-1.3.0-GitHub` целиком: папки `.github`, `src`, `client-fabric`, `resource-pack`, `docs`, файлы Gradle и остальные файлы в корне. Важно: загружайте именно содержимое папки проекта, а не ZIP-файл как один файл и не дополнительную внешнюю папку.
5. Введите сообщение коммита, например `Import EtherTV 1.3.0-dev`, и нажмите **Commit changes**.
6. Откройте вкладку **Actions**. Рабочие процессы сборки сервера и Fabric-клиента запускаются при изменении соответствующих исходников; их также можно запустить вручную через **Run workflow**.

## Сборка

- Серверный модуль: корень репозитория, Java 25, Gradle 9.2.1.
- Fabric-клиент: каталог `client-fabric`, Java 25, Gradle 9.2.1.
- Результаты успешной сборки появятся во вкладке конкретного запуска Actions в разделе **Artifacts**.
- В проекте нет Gradle Wrapper; GitHub Actions устанавливает Gradle через `gradle/actions/setup-gradle`.

## Важные замечания

- Это development-исходники, а не проверенный релиз. См. `VALIDATION_REPORT_RU.md` и `README.md`.
- Workflow проверяет компиляцию; он не заменяет запуск на тестовом Paper-сервере и проверку с Fabric-клиентом.
- Файлы сторонних зависимостей в `libs/` и `external-dependencies/` оставлены такими, какими они были в исходном проекте. Перед публичной публикацией проверьте лицензии и право распространять каждый бинарный файл. Если права нет, удалите бинарник из репозитория и укажите официальную инструкцию получения зависимости.
- В репозиторий намеренно не добавлен `LICENSE`: владелец проекта должен выбрать лицензию. Не публикуйте проект как open source с подразумеваемой лицензией, пока это решение не принято.
