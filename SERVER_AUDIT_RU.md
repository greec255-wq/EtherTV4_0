# EtherTV 1.2.0-dev — аудит серверной части

Дата проверки: 18.11.2026

## Что проверено

- Структура Paper-плагина, `paper-plugin.yml`, `config.yml` и Gradle-конфигурация.
- Серверный жизненный цикл плагина, команды, камера ЭК-1, архив, карта-экран и сеть громоотводов.
- Обмен `ethertv:bridge`, приём JPEG/PCM и ограничения размеров пакетов.
- Наличие API Custom Discs 2.7.0 в приложенном JAR. В API подтверждены `CustomDiscsAPI.get()` и `isCustomDisc(ItemStack)`; PDC-ключи `customdiscs:local` и `customdiscs:remote` присутствуют в интеграции проекта.

## Исправлено в этом аудите

1. `client-capture.prefer-client-framebuffer` теперь действительно управляет выбором кадров: при `false` сервер использует резервную трассировку блоков даже у игрока с EtherTV Client.
2. `client-capture.max-frame-bytes` и `client-capture.max-game-audio-bytes` теперь применяются на входе сетевого моста и при передаче данных в активную запись. Значения не могут превысить жёсткие пределы протокола: 400 000 байт для JPEG и 48 000 байт для PCM.

## Подтверждённые ограничения

- Серверная часть не собрана: в среде проверки установлен только Java 21, а Gradle отсутствует. Для целевой Paper 26.2 требуется Java 25; Gradle 9.1 или новее поддерживает запуск на Java 25.
- В проекте пока нет Gradle Wrapper (`gradlew` / `gradlew.bat`), поэтому команда сборки не закреплена внутри архива.
- Совместимость API Simple Voice Chat 2.6.1 и Paper 26.2 пока не подтверждена компиляцией.
- Работа Custom Discs проверена на уровне доступного API и дескриптора плагина, но не проверена на живом сервере.
- Этот аудит не является runtime-тестом: нет подтверждения загрузки плагина, записи на сервере или проигрывания архива в Minecraft.

## Вывод

Серверная часть прошла статическую проверку исходников и получила два исправления конфигурации. Этап нельзя считать полностью закрытым до сборки на Java 25 с Gradle 9.1+ и запуска на тестовом Paper 26.2 с Custom Discs 2.7.0 и Simple Voice Chat 2.6.1.
